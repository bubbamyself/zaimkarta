# Контракт postback LeadGid

Дата фиксации: 31 июля 2026 года.

Источник: справка и форма «Новый глобальный постбек» в личном кабинете LeadGid.
Секреты, токены и персональные данные в документе отсутствуют.

## Подтверждённые события

- `Новая конверсия` — уведомление о вновь созданной конверсии.
- `Обновление статуса` — уведомление при изменении статуса существующей конверсии.
- `Обновление выплаты` — уведомление при изменении суммы выплаты.

Для одной интеграции следует использовать либо глобальный, либо индивидуальный
postback. Одновременная настройка обоих вариантов дублирует уведомления.

## Используемые макросы

| Данные | Макрос LeadGid | Параметр ZaimKarta |
| --- | --- | --- |
| Уникальный цифровой ID лида | `{lead_id}` | `conversion_id` |
| ID клика LeadGid, hex 30 символов | `{transaction_id}` | `transaction_id` |
| Наш `sub2 = clickId` | `{aff_sub2}` | `click_id` |
| Наш `sub3 = slug` | `{aff_sub3}` | `offer_slug` |
| ID оффера LeadGid | `{offer_id}` | `offer_id` |
| Исходный статус | `{status}` | `status` |
| Сумма выплаты | `{payout}` | `payout` |
| Валюта оффера | `{currency}` | `currency` |

LeadGid также возвращает `{aff_sub}` (наш `sub1 = leadId`), но обработчику он
не нужен: связь выполняется по более точному `click_id`.

## Шаблон URL

В кабинете LeadGid следует указать URL одной строкой, заменив `<SECRET>` на
отдельный production-секрет:

```text
https://zaimkarta.ru/api/postback/leadgid?secret=<SECRET>&conversion_id={lead_id}&transaction_id={transaction_id}&click_id={aff_sub2}&offer_slug={aff_sub3}&offer_id={offer_id}&status={status}&payout={payout}&currency={currency}
```

Форма LeadGid принимает URL и не предлагает выбор HTTP-метода или заголовка
авторизации. Поэтому ZaimKarta принимает `GET`, а подлинность проверяет по
секретному параметру URL. Приложение не пишет URL или payload в свои логи.

Успешный, повторный или неизвестный по `click_id` postback получает HTTP 200.
Поддельный запрос получает HTTP 401, некорректный контракт — HTTP 400,
временная серверная ошибка — HTTP 503.

## Нормализация статусов

В форме LeadGid показаны три статуса конверсии:

| Исходный статус | Статус ZaimKarta |
| --- | --- |
| `На проверке` | `PENDING` |
| `Подлежит оплате` | `APPROVED` |
| `Отклонён` | `REJECTED` |

Любое другое значение сохраняется без изменений и получает категорию
`UNKNOWN`. Категория `PAID` зарезервирована для отдельного подтверждения факта
выплаты, которого текущий postback-контракт LeadGid не передаёт.

## Ограничение известного контракта

В доступной справке не описаны подпись запроса, уникальный ID события,
гарантированный формат успешного ответа и график повторных попыток. Поэтому
идемпотентность строится на внешнем ID конверсии и переходе между предыдущим и
новым состоянием статуса/выплаты. После выкладки нужно выполнить встроенное
тестирование LeadGid и зафиксировать фактическое строковое значение `{status}`.
